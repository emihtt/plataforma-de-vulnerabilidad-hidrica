Dos experiencias funcionales con cinco entradas: gestión para organizaciones, financiadores y gobiernos; consulta para comunidades y quienes cuidan la cuenca. El selector de vista no autentica usuarios ni implementa permisos de servidor.

Cambios de esta entrega

  • Selección de perfil, mapa y priorización con variables graduales. La primera variable es carencia de agua entubada; solo las activas participan en el índice.
  • Tres escalas disponibles: localidades censales, una unidad regional modelada y once unidades de detalle modeladas. HydroBASINS v1c, niveles 6 y 12; no son delimitaciones oficiales mexicanas. Las 72 localidades quedaron adscritas una sola vez en cada escala.
  • Línea base y fichas imprimibles por territorio, con cobertura y fuentes. Los agregados solo representan localidades de Valle de Bravo: se suman numeradores y denominadores válidos, no porcentajes ni grados de marginación.
  • Registro, edición, archivo y reactivación de proyectos. Intervenciones y aportes financieros separados; metas por componente sin duplicarlas por financiador y sin afirmar personas únicas.
  • Indicadores definidos por unidad, universo, método y fuente; mediciones fechadas, tabla y gráfica. Sin imputar faltantes ni calcular cambio relativo con base cero. Ningún cambio acredita causalidad.
  • Tres proyectos ficticios, uno por escala. Dinero, metas y series están señalados como ilustrativos en vistas e impresiones. Nuevos registros locales sin verificar, guardados en el navegador; exportación/importación JSON versionada.
  • Se mantienen las correcciones anteriores: intervalo de almacenamiento, lluvia no homogénea, fechas de presa, límites de captación y ausencia de financiamiento o alianzas aseguradas.

Fuentes, permisos y límites concretos

Los servicios oficiales consultados respondieron 503 (IDEFOR) y 403 (CONAGUA). Se usó la alternativa modelada autorizada. Los ZIP continentales quedan fuera de Git; la aplicación incorpora un subconjunto derivado, atribuciones y la licencia original en sitio/licencias/.

El piloto no mide toda una cuenca, no identifica beneficiarios únicos, no verifica proyectos ni fondos y no prueba impacto. No se agregan marginación, distancia o captación a cuencas sin un método validado. Las unidades sin localidades con datos no se convierten en valores cero ni entran al ranking.

Cómo reproducir

En el repositorio: npm ci, npm run build, npm test y python -m pytest pipeline/tests -q. Servir dist por HTTP y ejecutar python scripts/qa_demo.py http://127.0.0.1:4173/ con Playwright/Chromium instalados. No es necesario ejecutar el pipeline de descargas para abrir esta candidata.

El paquete se crea con scripts/preparar_demo.py, usando un runtime CPython existente y conservando su licencia. No modifica el entorno del sistema.
